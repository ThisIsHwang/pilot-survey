# Qwen3.5 행동 후보와 입력 상태의 출처

## 왜 이 구분이 필요한가

기존 causal-query 상태 파일에는 이전 정책이 만든 검색 기록이 들어 있을 수 있습니다. 그 파일의 factual query를 그대로 사용하면 Qwen2.5가 만든 검색어를 Qwen3.5 행동으로 잘못 세는 문제가 생깁니다.

## 이번 5일 실험의 처리 방식

- 이전 상태 파일은 **고정된 평가 문맥**으로만 사용합니다.
- 개입 시점의 기존 factual query는 주 분석 후보에서 제외합니다.
- 통제형 source candidate도 주 분석에서 사용하지 않습니다.
- 비교하는 검색 행동은 모두 같은 고정 상태에서 비사고 모드 Qwen3.5-9B가 직접 생성합니다.
- 설정 게이트는 직접 Qwen3.5 행동 비율을 1.0으로 요구합니다.

따라서 이번 결과가 답하는 질문은 다음입니다.

> 주어진 고정 검색 상태에서 Qwen3.5가 생성한 여러 검색 행동을 비교할 때, 각 행동이 가져온 문서의 크레딧이 행동의 결과 크레딧을 대신할 수 있는가?

## 주장 경계

이 설계는 행동 후보의 모델 출처를 깨끗하게 만들지만, Qwen3.5가 처음부터 직접 방문한 상태만을 사용한 완전한 on-policy 실험은 아닙니다.

- **on-policy 상태**: 현재 검사하는 모델이 직접 생성한 궤적에서 방문한 상태
- **고정 외부 상태**: 다른 정책이 만들었을 수도 있지만 모든 비교 조건에 동일하게 제공되는 상태

따라서 5일 실험만으로 “Qwen3.5가 실제 배포 중 방문하는 모든 상태에서도 같은 효과가 난다”고 주장하지 않습니다. 논문의 최종 보강 단계에서는 Qwen3.5가 처음부터 생성한 궤적에서 작은 복제 실험을 추가하는 것이 좋습니다.
